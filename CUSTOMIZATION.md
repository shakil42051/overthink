# Customization and cleanup

Open **Settings → Customize your workspace**, or the customization link on Home. Search settings or browse Style, Home, Discovery, Library, Reader, and Privacy. All 34 preferences are persisted locally and validated when loaded. Resetting preferences leaves workspaces and credentials intact. Device preferences are separate from synchronized account data.

| Area | Working controls |
| --- | --- |
| Style | System/light/dark; five accent palettes; modern/editorial headings; 85–130% text scale on top of Android's scale; comfortable/compact spacing; three corner styles; reduced motion; three transition speeds; navigation/bookmark haptics |
| Home | Launch destination; spotlight, library, projects, and search-history sections |
| Discovery | Default paper/dataset/code search; paper provider; optional starting year (blank means all years); PDF-only default; sorting of loaded records |
| Library | Default collection; four sort orders; author, abstract, and metadata visibility; 1–5 preview lines; BibTeX/RIS/Markdown export; removal confirmation |
| Reader | Original/sepia/night rendering; opening zoom; keep-screen-awake; remembered page; double-tap zoom; initial focus mode |
| Privacy | Search history opt-out and history clearing |

Reading themes change the displayed PDF bitmap, not the original file. Reader controls are pinned outside the page viewport. Tap the page to reveal tools, tap the page count to jump, and pinch to zoom. Saved sources have favorites, three reading statuses, editable tags, and collection assignment. Notes can be edited. Library exports use the currently filtered list. RIS exports use a generic record type and a provider-supplied author string; verify citation metadata before submission.

Exports are staged atomically in the app's private cache before opening Android's document picker. Recreating the activity or export helper does not turn the export into an empty file. The staged copy is removed after successful export or cancellation.

Search defaults apply to fresh sessions. Current searches can be refined in Discover. Sorting applies to records already fetched, rather than claiming provider-wide ranking. Paper-only defaults do not restrict dataset or code searches. Turning history off clears the active workspace's recent searches and prevents new history writes; other account workspaces remain separate.

## Cleanup evidence

The user explicitly requested removal of old, unwanted, unused code after authorizing the rebuild. Before removal, read-only inspection established:

- `settings.gradle.kts` includes only `:app`. The app uses default source/resource directories under `app/src`; no source sets, manifest references, scripts, server code, or workflow references point to the old archive or AI Studio scaffolding.
- `legacy/android-v1` held 75 original source/configuration files (1,616,991 bytes), already excluded from compilation. Only historical audit and README references pointed to it; those references were updated before cleanup. The runtime legacy database importer is independent Kotlin/SQLite code in the new app and is retained.
- `.aistudio` contained the superseded implementation plan and its metadata. Root `assets` contained only an AI Studio ignore file. Root `metadata.json` and `.env.example` described the obsolete AI Studio runtime. The active backend uses `server/.env.example`, which is retained.
- `.tooling/jdk21.zip` was a redundant 196,945,976-byte download. The extracted `.tooling/jdk-21.0.12.1/bin/java.exe` is used successfully for builds and is retained.

Removing these files reduces workspace clutter. They were already excluded from the APK; production size is controlled by release shrinking, minimal dependencies, and the native UI. Gradle/SDK caches, the working JDK, formatter, active assets, and existing device databases are retained.

The extended icon catalog was also replaced by the 21 used AndroidX vector sources (49,965 source bytes) and the small core icon library. Unused preview-only production dependencies and template ProGuard comments were removed. Release builds use code and resource shrinking. See `THIRD_PARTY_NOTICES.md` for origin and licensing.

Release validation exposed missing optional JVM TLS-provider classes referenced by OkHttp 4.10.0. Its [version-specific platform selector](https://github.com/square/okhttp/blob/parent-4.10.0/okhttp/src/main/kotlin/okhttp3/internal/platform/Platform.kt) selects the Android platform on Android, separately from these optional JVM providers. The build adds only the nine exact missing-class rules generated by R8; TLS verification and lint remain enabled. The local check script and CI now build and lint the release variant as well as debug.

The device smoke test exposed a dialog-window measurement problem that clipped the reader toolbar below the display. The reader now occupies the main activity viewport; source-detail drafts are saved while it is open, and the background screen is removed from the accessibility tree. A toolbar-visibility regression test covers the error/loading state too. The year filter uses an explicit all-years default; setting 1900 now applies an actual date floor, and undated papers are excluded only when a date filter is selected.
